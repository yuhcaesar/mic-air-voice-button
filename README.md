# AirKey · 语音键

**中文** | [English](README.en.md)

把 **Insta360 Mic Air 接收器的音量＋按键**变成豆包输入法的语音快捷键。

当前版本：**v1.4.0**。适用于 Intel / AMD **Windows x64**。提供独立 EXE，日常使用无需安装 AutoHotkey。

原创代码使用 MIT 许可；成品中的 Interception 驱动和安装器适用上游的非商业使用条件。商业用途需另行取得上游授权，详见[第三方许可](THIRD_PARTY_NOTICES.md)。

## 能做什么

- 一键启用、暂停；绿色状态显示当前是否开启。
- 默认发送 **右 Alt＋空格**，支持录入其他快捷键，区分左右 Alt、Ctrl、Shift。
- 首次使用跟随向导识别按钮并试用；确认豆包语音启动且音量不变后，才保存设置并启用。
- 首次使用默认 **标准模式（推荐）**；需要时可在设置中选择 **兼容模式**，切换后重新试用并确认。
- 无需选择设备编号；试用不成功时可继续尝试其他本机连接。切换模式是单独的选择，不会自动切到兼容模式。
- 每台电脑独立保存经过确认的配置；连接仍有效时，下次打开恢复之前的启用状态。
- 默认中文，点击主界面右下角的 **English / 中文** 按钮切换语言；记住选择，切换时语音按钮继续工作。
- 最小化后收进系统托盘；单击托盘图标恢复界面，右键打开菜单。
- 提供“重新识别按钮”和“卸载并恢复”。

## 第一次使用

1. 从 [Releases](https://github.com/yuhcaesar/mic-air-voice-button/releases) 下载并打开 `AirKey.exe`，连接 Mic Air 接收器。在豆包输入法中，将语音输入的免按模式快捷键设为 **右 Alt＋空格**。
2. 点击 **安装并启用**，允许 Windows 的管理员提示。
3. 安装成功后，保存工作并**手动重启 Windows**，再打开程序。驱动就绪后，按钮设置向导会自动打开。
4. 默认使用 **标准模式（推荐）**。按一次 Mic Air 按钮，让程序识别按钮。
5. 点击向导中的输入框，再按一次 Mic Air 按钮，试着启动豆包语音。
6. 确认 **豆包已启动，而且音量不变、音量条不弹出**，再点击 **两项正常，完成设置**。豆包未启动时点击 **豆包未启动，换一种方式**，在当前模式下试用下一种连接；若音量仍变化，点击 **音量仍在变化**，本次结果不会保存。

标准模式无法完成设置时，可在向导中明确选择 **改用兼容模式**，重新识别按钮并试用；程序不会自动替你切换。也可以从兼容模式切回标准模式。

只有收到真实按钮事件、完成试用并由你同时确认语音和音量正常后，程序才保存本机配置并启用；AirKey 不会自动检测豆包是否开始录音。向导输入框的内容不会被 AirKey 保存。已经安装并加载所需驱动时，无需重装，直接完成按钮设置即可；取消后可点击 **设置语音按钮** 重新开始。

最小化后收进系统托盘并继续运行，单击托盘图标即可恢复界面。图标可能位于 Windows 托盘的“隐藏图标”区域。再次双击 EXE 也会恢复已有窗口，不会多开。

关闭窗口或在托盘菜单选择“退出程序”会停止映射并退出。程序不会自动重启电脑，也不会设置 Windows 开机自启动。

### 语言与升级

AirKey 默认中文。点击主界面右下角的 **English** 按钮即可切换英文；英文界面中点击同一位置的 **中文** 按钮切回。程序会记住选择，无需打开设置、重启程序或暂停已启用的语音按钮。主界面、按钮设置向导、托盘菜单、快捷键录入窗口和应用自带提示均提供两种语言；向导使用打开时的语言，关闭后可切换。“使用说明”会打开当前语言的说明文件。Windows 自带的权限等对话框遵循系统语言。

中文应用标题为 **AirKey · 语音键 — Insta360 Mic Air**，英文为 **AirKey — Insta360 Mic Air**。

从旧版升级时，先退出旧程序和独立音量实验工具，再用 `AirKey.exe` 替换旧 EXE。已安装且正常工作的驱动无需重装。v1.4.0 保留本机仍有效、已确认“语音启动且音量不变”的配置：原来使用兼容方式的配置继续使用兼容模式，不会被改成标准模式。旧版只确认语音的配置仍需重新验证。原有快捷键和语言设置继续保存在 `%LOCALAPPDATA%\MicAirDoubao`，目录名保持不变以兼容老用户。仓库地址仍为 `yuhcaesar/mic-air-voice-button`。

每台电脑单独保存自己的验证结果。换电脑、原来的连接消失，或保存的连接不再能被确认时，需要重新跟随向导试用；复制 EXE 或旧配置不能代替新电脑上的验证。

### 选择模式

打开 **设置**，选择 **标准模式（推荐）** 或 **兼容模式**。

- **标准模式（推荐）**：首次设置的默认选择，接收按钮后直接触发语音快捷键。
- **兼容模式**：标准模式无法正常工作时可试用，通过麦克风的媒体按钮信号接收操作，并同时启用音量拦截。

选择另一种模式会打开设置向导。重新识别按钮，在输入框中按按钮试用，确认 **语音启动、音量不变且音量条不弹出** 后，才保存新模式并启用。取消切换会保留原来的配置，并恢复切换前的启用或暂停状态。首次设置还没有可恢复的配置时，取消后保持未设置。

模式决定如何接收按钮；向导中的连接试用则是在该模式下尝试让豆包响应。点击 **豆包未启动，换一种方式** 只尝试下一种连接，不会切换模式。两者都不需要你识别设备编号。

兼容模式的音量拦截也会影响通过同一通道到达的其他来源音量＋；调音量请用系统滑块。切回标准模式同样需要重新试用并确认。

### 修改快捷键

打开 **设置 → 修改 → 开始录入**，按下你在豆包中设置的组合，然后保存。更改快捷键后需要重新完成按钮设置，确认新组合能启动豆包语音。

**本工具与豆包输入法的快捷键必须一致。**这里修改的是本工具发送的按键，不会改动豆包自己的设置。

### 重新识别按钮

按钮没有反应或需要重新适配时，打开 **设置 → 重新识别按钮**。向导会在当前模式下重新识别 Mic Air 按钮，并让你逐一试用可用连接；点击 **两项正常，完成设置** 后才保存新的结果。需要另一种模式时，请明确选择切换模式。它不会改动你选择的快捷键，也不会自动判断豆包是否启动。

### 检查旧版为何没有响应

可使用独立的 [AirKey 按钮检测工具](diagnostics/README.md)。它分别检查原始信号、旧版接收逻辑、系统热键、键盘监听和快捷键输出，生成可分享的脱敏报告；不会安装驱动或修改 AirKey 设置。结果反映本次测试，不能单凭某一种方式成功就认定历史故障原因。[下载检测工具](https://github.com/yuhcaesar/mic-air-voice-button/releases/tag/diagnostics-v0.1.1)。

### 恢复音量键 / 卸载

- 临时停用：点击 **暂停语音按钮**，停止触发语音并解除音量拦截。
- 彻底移除：点击 **卸载并恢复**，完成后手动重启 Windows，再删除 EXE。
- 设置、日志和运行组件保存在 `%LOCALAPPDATA%\MicAirDoubao`。卸载驱动并退出程序后，可以删除这个程序专用目录。

不要手动删除 Windows 系统目录里的驱动文件。卸载 Interception 会同时影响其他使用该驱动的应用。

## 使用前了解

- 标准模式也会接管其他可收到的音量＋，键盘音量＋可能触发语音。模式只在你明确选择并完成验证后改变，标准模式不会自动转为兼容模式。
- 兼容模式接收已识别麦克风的媒体按钮信号，同时启用内置音量拦截器。拦截处理所有到达该通道的音量＋命令，无法只区分 Mic Air，其他来源的音量＋也可能受影响。需要调音量时可使用系统滑块。暂停、退出或接收失败时解除拦截，不需要另开实验工具。
- 某些软件自行处理媒体按键或使用不同系统通道，可能绕过拦截。请在常用软件确认效果；若音量仍变化，应暂停并重新设置。程序不会采用“变大后再调回”的补偿方式。首次识别按钮时可能改变一次音量；兼容模式在后续试用时启用拦截。
- 两次触发至少间隔约 1.5 秒，避免一次按压重复触发。
- 只发送快捷键，不录音、不上传数据、不记录普通打字内容，也不检测豆包是否正在录音。
- 需要管理员权限安装 / 卸载驱动；首次安装及卸载后需要重启。
- 基础触发方式已在一台 Windows 11 x64 电脑配合 Mic Air 接收器实测成功；不能保证所有电脑兼容。只有在该电脑上收到按钮事件并由用户确认豆包语音启动且音量不变，才算完成该机设置。长期休眠与反复热插拔尚未全面验证。
- Interception v1.0.1 较旧；[Kanata 的 Windows 已知问题](https://github.com/jtroo/kanata/blob/main/docs/platform-known-issues.adoc)记录了相关驱动在部分系统上出现的休眠、设备插拔问题。
- Windows on ARM 不适用。EXE 未做代码签名；设置向导无法自动解决驱动被系统拦截的问题。如果系统阻止驱动加载，请停止安装或卸载，保持系统安全防护开启。

## 为什么需要驱动

在本项目的测试环境中，Mic Air 通过接收器上报音量＋，普通软件模拟快捷键没能启动豆包语音。两种模式都通过 Interception 发送键盘扫描码。标准模式使用系统注册热键或键盘钩子接收按钮；兼容模式使用 Windows Raw Input 接收媒体按钮信号，并同时启用项目自带的 WH_SHELL 音量命令拦截器。选择兼容模式无需新增驱动。

默认右 Alt＋空格沿用已经验证成功的发送顺序。程序不使用 Interception 拦截原始键盘输入，也不需要更改豆包程序。

## 从源码构建

安装 [AutoHotkey v2 x64](https://www.autohotkey.com/) 和 [Ahk2Exe](https://github.com/AutoHotkey/Ahk2Exe)，然后在仓库目录运行：

```powershell
.\build.ps1
```

产物为 `dist\AirKey.exe`。可用 `-Runtime`、`-Compiler` 指定工具路径，或设置 `AHK_RUNTIME` / `AHK_COMPILER` 环境变量。构建不会安装驱动，也不会运行产物。

本次发布使用 AutoHotkey **2.0.30 x64** 与 Ahk2Exe **1.1.37.02a2**。第三方依赖版本、许可及来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

仓库包含预编译的 `assets/volume-guard.dll`，其源码为 `native/volume-guard.c`，按本项目 MIT 许可提供。需要重建时，安装 Windows x64 [TinyCC 0.9.27](https://download.savannah.gnu.org/releases/tinycc/)，运行：

```powershell
.\native\build-volume-guard.ps1 -NativeCompiler 'D:\Tools\tcc\tcc.exe'
.\native\tests\run-tests.ps1 -NativeCompiler 'D:\Tools\tcc\tcc.exe'
```

将生成的 DLL 的 SHA256 更新到 `Main.ahk`，然后重新运行 `build.ps1`。此 DLL 仅调用 Windows 系统 API，不链接编译器运行库；构建和隔离测试均不会启用音量拦截或发送真实按键。

### 第三方组件源码与重新构建

每个成品 Release 同页提供 `ThirdParty-Sources.zip`，其中包含对应版本的 AutoHotkey 和 Interception 上游源码。它们与本仓库源码一起构成重新构建所需的源码材料；构建工具链按各上游说明安装。

如果修改 Interception API DLL，请先依据其上游源码构建 x64 DLL，再替换本仓库的 `assets/interception.dll`，并将 `Main.ahk` 中该 DLL 的 SHA256 校验值更新为新文件的值，然后运行 `build.ps1`。如果修改 AutoHotkey，请根据随附上游源码说明构建 x64 解释器，再通过 `build.ps1 -Runtime <路径>` 指定它。源码层面的修改和重新构建不需要本项目授予额外许可，第三方组件仍遵守各自许可。

当前 EXE 会解包并校验内置组件，直接替换运行目录的 DLL 会被覆盖；请使用上述重新构建方式。本项目不限制为调试用户修改而进行的合法逆向工程。

### 测试

```powershell
.\tests\run.ps1
```

测试包括语法验证、快捷键解析、发送顺序、失败时释放按键、配置保存和停止逻辑，以及双语和隐藏向导窗口检查。发送由内存模拟替代；不会安装驱动、发送真实快捷键或修改日常设置。

真正的 Mic Air 按钮、豆包语音触发以及安装 / 卸载流程需要人工验证。独立音量实验工具已由用户在另一台电脑确认“豆包启动且音量不变”；正式集成后的设置仍需在目标电脑确认，不能据此保证所有电脑或软件兼容。
