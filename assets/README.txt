AirKey · 语音键 v1.3.0
中文应用标题：AirKey · 语音键 — Insta360 Mic Air
English: README.en.txt

用途
把 Mic Air 接收器发出的“音量＋”按键转换成豆包语音的启动快捷键。
默认快捷键为“右 Alt＋空格”，可在本工具的“设置”中修改。
默认组合此前已由用户实测成功；独立音量拦截实验也在另一台电脑确认语音正常、音量不变。正式集成后仍需目标电脑确认。
程序不录音、不上传数据、不记录普通打字内容。

第一次使用
1. 把 AirKey.exe 放到想保留的位置，双击打开。
   EXE 已包含运行组件，不需要单独安装 AutoHotkey。
2. 首次使用点击“安装并启用”，在 Windows 管理员提示中允许。
3. 安装成功后，保存工作并手动重启 Windows，再打开 EXE；驱动就绪后会自动打开按钮设置向导。
4. 在豆包设置中把免按模式设为“右 Alt＋空格”，与本工具的默认组合一致。
5. 按一次 Mic Air 按钮，让程序识别按钮。
6. 点击向导里的输入框，再按一次 Mic Air 按钮，试着启动豆包语音。
7. 确认豆包已启动、音量不变且音量条不弹出时，点击“两项正常，完成设置”，程序才会保存本机配置并启用。
   没有启动时，点击“豆包未启动，换一种方式”，再在输入框里按按钮试用。
   程序会依次尝试本机可用连接，不需要选择设备编号。
已经安装并加载所需驱动时，无需重装，直接完成向导即可。
音量仍变化时，点击“音量仍在变化”，本次结果不会保存。首次识别可能改变一次音量，后续试用会启用拦截。
只有收到真实按钮事件、完成试用并由你确认语音和音量都正常，才算完成这台电脑的设置。
AirKey 不会自动检测豆包是否开始录音，也不会保存向导输入框中的内容。
取消向导后，可点击“设置语音按钮”重新开始。
主界面用带有 Insta360 字样的麦克风示意插图及本机已安装的豆包输入法图标展示“Mic Air 按钮 → 豆包输入法”，
并显示当前快捷键和开关状态。
点击同一个主按钮即可启用或暂停。

语言与升级
默认中文。点击主界面右下角“English”切换英文，再点同一位置“中文”切回。
程序会记住选择，不用打开设置或重启程序，切换时不会暂停语音按钮。
主界面、按钮设置向导、托盘菜单、快捷键录入窗口和应用自带提示均支持两种语言。
向导使用打开时的语言，关闭后可切换。
“使用说明”会打开当前语言的说明文件；Windows 自带的权限等对话框遵循系统语言。
英文应用标题为 AirKey — Insta360 Mic Air。
从旧版升级时，先退出旧程序和音量实验工具，再用 AirKey.exe 替换旧 EXE；已安装且正常工作的驱动无需重装。
升级到 v1.3.0 需重新确认“语音启动且音量不变”，旧版只验证语音的配置不能直接通过。
原有快捷键和语言设置继续使用 %LOCALAPPDATA%\MicAirDoubao，保留目录名以兼容老用户。
每台电脑独立保存自己的验证结果。换电脑、原连接消失或无法确认保存的连接时，需要重新跟随向导试用。
复制 EXE 或旧配置不能代替新电脑上的验证。

日常使用
向导确认成功后，程序会保存本机配置。连接仍有效时，下次打开 EXE 会尝试恢复已启用状态。
点击“暂停语音按钮”会记住停用状态，下次打开也保持停用。
最小化后收进系统托盘并继续工作；单击托盘图标恢复界面，右键打开菜单。
图标可能位于 Windows 托盘的“隐藏图标”区域；再次双击 EXE 也能恢复已有窗口。
关闭窗口或在托盘菜单选择“退出程序”，会停止映射并退出。
本工具不设置 Windows 开机自启动，也不会自动重启电脑。
请勿同时运行旧版 driver-bridge.ahk 或其他音量键映射程序。
新版本会阻止自身多开，并提示先关闭已知旧版测试窗口。

设置
修改快捷键：打开“设置”，找到“启动豆包的快捷键”，点击“修改”，
按下想使用的组合并保存。录入可区分左右修饰键，并搭配支持的常见按键。
这里保存的是本工具发送的组合，不会修改豆包自身设置。
请在豆包中把免按快捷键设为相同组合；两边一致才能启动语音。
更改快捷键后，需要重新完成按钮设置，确认新组合能启动豆包语音。

重新识别按钮：按钮没反应或需要重新适配时，在“设置”中点击此项。
它会重新识别按钮，并让你逐一试用可用连接，不改变你选择的快捷键。
只有在向导输入框里按 Mic Air 按钮时才试发快捷键；点击“两项正常，完成设置”后才保存新结果。
如果没有启动，点击“豆包未启动，换一种方式”。程序不会自动判断豆包是否已经启动。
仍无法完成时，请确认手动快捷键可用、两边设置一致，并检查接收器连接。
展开、收起设置不会中断正在使用的语音按钮。

恢复与卸载
临时停用：点“暂停语音按钮”，立即停止触发语音，无须重启；同时解除音量拦截。
彻底移除驱动：点“卸载并恢复”，允许 Windows 管理员提示，
等待成功后手动重启；然后退出并删除 EXE 即可。
程序设置、日志及解包组件位于 %LOCALAPPDATA%\MicAirDoubao。
卸载驱动、退出程序后，该程序专用文件夹也可以手动删除。
请通过程序或官方安装器卸载，不要直接删除 Windows 系统驱动文件。
卸载 Interception 会影响此电脑上其他使用同一驱动的应用。

限制
- 当前包为 Intel/AMD x64 版；Windows on ARM 不适用。
- 接收方式由向导自动识别，无需手动选择。
  键盘按键模式会接管所有可接收到的“音量＋”，键盘音量＋也会触发语音。
  设备媒体信号方式会启用内置音量拦截器，无需单独运行实验工具。
  它会接管到达该通道的所有音量＋命令，无法只区分 Mic Air；调音量请用系统滑块。
- 两次按键至少间隔 1.5 秒，避免一次按钮触发多次。
- 程序只发送启动快捷键，不检测豆包是否正在录音。
- 更换电脑需要在新电脑准备驱动并重新完成向导；按钮无法响应时，打开“设置”点击“重新识别按钮”。
- 不能保证所有电脑兼容。只有该机收到按钮事件并由用户确认豆包语音启动且音量不变，才算设置成功。
- Interception v1.0.1 较旧，作者测试范围截至 Windows 10。
  Kanata 文档记载 Windows 11 多次休眠或设备插拔后输入失效的问题。
  长期休眠、热插拔及所有应用场景尚未全面验证；部分软件可能绕过音量拦截。
- 此自行打包的 EXE 没有数字签名，Windows 可能显示发布者未知。
  向导无法自动解决驱动被系统拦截的问题。若系统阻止驱动加载，请停止安装或卸载，不要关闭系统安全防护。

按钮如何接收
同时检查系统注册热键、键盘钩子及原始媒体信号，实际收到事件后才选择；后者配合内置音量拦截。
这些方式都通过 Interception 发送你设置的快捷键；不使用 Interception 拦截原始键盘输入。
安装或卸载驱动仍需管理员权限和手动重启，首次适配向导不能绕过这些要求。

从源码构建与测试
在源码目录安装好 AutoHotkey v2 x64 和 Ahk2Exe 后运行 .\build.ps1，产物为 dist\AirKey.exe。
可使用 -Runtime、-Compiler 指定工具路径；构建不会安装驱动或运行产物。
运行 .\tests\run.ps1 可进行本地检查，按键发送由模拟替代，不修改日常设置或驱动。
修改 Interception DLL 后须同步更新 Main.ahk 的校验值并重新构建；直接替换运行目录的 DLL 会被覆盖。
完整构建步骤、上游源码及许可说明见仓库 README 和对应 Release。
