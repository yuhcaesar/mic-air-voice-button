Mic Air 语音按钮 v1.0.7

用途
把 Mic Air 接收器发出的“音量＋”按键转换成豆包语音的启动快捷键。
默认快捷键为“右 Alt＋空格”，可在本工具的“设置”中修改。
默认组合的驱动发送方式已在本机由用户实测成功。
程序不录音、不上传数据、不记录普通打字内容。

第一次使用
1. 把 MicAirDoubao.exe 放到想保留的位置，双击打开。
   EXE 已包含运行组件，不需要单独安装 AutoHotkey。
2. 首次使用点击“安装并启用”，在 Windows 管理员提示中允许。
3. 安装成功后，保存工作并手动重启 Windows，再打开 EXE。
4. 在豆包设置中把免按模式设为“右 Alt＋空格”，与本工具的默认组合一致。
5. 程序自动沿用可用配置，点击“启用语音按钮”。
6. 点击文本框，按一下 Mic Air 按钮，观察豆包语音是否启动。
主界面用原创麦克风示意插图及本机已安装的豆包输入法图标展示“Mic Air 按钮 → 豆包输入法”，
并显示当前快捷键和开关状态。
点击同一个主按钮即可启用或暂停。

日常使用
启用成功后，程序会保存本机配置。下次打开 EXE 会尝试恢复已启用状态。
点击“暂停语音按钮”会记住停用状态，下次打开也保持停用。
最小化窗口后继续工作；关闭窗口或退出托盘程序会立即停止映射。
本工具不设置 Windows 开机自启动，也不会自动重启电脑。
请勿同时运行旧版 driver-bridge.ahk 或其他音量键映射程序。
新版本会阻止自身多开，并提示先关闭已知旧版测试窗口。

设置
修改快捷键：打开“设置”，找到“启动豆包的快捷键”，点击“修改”，
按下想使用的组合并保存。录入可区分左右修饰键，并搭配支持的常见按键。
这里保存的是本工具发送的组合，不会修改豆包自身设置。
请在豆包中把免按快捷键设为相同组合；两边一致才能启动语音。

修复按钮响应：仅在按钮没反应或连接发生变化时使用，正常使用无需点击。
它会重新查找当前可用于发送快捷键的连接，不改变你保存的快捷键。
修复会短暂暂停功能，成功后恢复先前的开启状态；不会发送测试按键。
如果仍无法恢复，请重新连接接收器，或重启电脑后再试。
展开、收起设置不会中断正在使用的语音按钮。

恢复与卸载
只恢复音量键：点“暂停语音按钮”，立即生效，无须重启。
彻底移除驱动：点“卸载并恢复”，允许 Windows 管理员提示，
等待成功后手动重启；然后退出并删除 EXE 即可。
程序设置、日志及解包组件位于 %LOCALAPPDATA%\MicAirDoubao。
卸载驱动、退出程序后，该程序专用文件夹也可以手动删除。
请通过程序或官方安装器卸载，不要直接删除 Windows 系统驱动文件。
卸载 Interception 会影响此电脑上其他使用同一驱动的应用。

限制
- 当前包为 Intel/AMD x64 版；Windows on ARM 不适用。
- 所有能被脚本接收的“音量＋”键都会触发，暂未按 Mic Air 单独区分。
- 两次按键至少间隔 1.5 秒，避免一次按钮触发多次。
- 程序只发送启动快捷键，不检测豆包是否正在录音。
- 更换电脑需要在新电脑安装驱动；按钮无法响应时，打开“设置”点击“修复按钮响应”。
- Interception v1.0.1 较旧，作者测试范围截至 Windows 10。
  Kanata 文档记载 Windows 11 多次休眠或设备插拔后输入失效的问题。
  本机已验证触发功能；长期休眠、热插拔稳定性及其他电脑尚未验证。
- 此自行打包的 EXE 没有数字签名，Windows 可能显示发布者未知。
  若系统阻止驱动加载，请停止安装或卸载，不要关闭系统安全防护。
